# Frameworks — Borrowed vs. Invented

**Default**: use established frameworks. The value is in application, not invention. A piece that applies the Pyramid Principle well is worth more than one that coins a new acronym.

Common ones worth reaching for first:
- **Pyramid Principle** (Barbara Minto) — conclusion first, then support
- **SCQA** (McKinsey) — Situation, Complication, Question, Answer
- **JTBD** (Christensen) — jobs to be done
- **MECE** (McKinsey) — mutually exclusive, collectively exhaustive
- **Cynefin** (Snowden) — sense-making across simple/complicated/complex/chaotic

**Invent a new framework only when all of these hold:**
- You have genuinely discovered a pattern no one has named
- Existing frameworks do not capture the specific nuance
- You have evidence across multiple instances
- You are willing to refine it over time

**Challenger questions for framework usage:**
- "Is there an established framework that already covers this?"
- "What is genuinely novel here vs. repackaging existing wisdom?"
- "Would a senior consultant roll their eyes at this?"
- "If we use an existing framework, does the piece still have value?"

**Voice caution.** Naming a framework is a fast route into aphorism mode and the oracle posture (see `shared/AI-TELLS.md` Class 4). Coining "the [Adjective] [Noun] Framework" and presenting it as a discovery is a strong AI / self-promotion tell. If you are genuinely naming something, it should read as "I have started thinking of this as X" — a working label, not an unveiling.
