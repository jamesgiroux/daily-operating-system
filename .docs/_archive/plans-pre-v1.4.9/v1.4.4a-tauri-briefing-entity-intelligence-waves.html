DailyOS - v1.4.4a - Parallel Wave Plan

Tauri briefings consume scored entity intelligence.

Start with Daily Briefing and Meeting Briefing, then roll the same substrate-backed read contract into entity detail, actions, and email.

This plan turns the app surfaces into consumers of the abilities runtime instead of parallel readers of legacy intelligence projections. The first proof is not WordPress or MCP: it is the shipped Tauri experience. Daily Briefing and Meeting Briefing become the first two surfaces that read scored claims, provenance, trust bands, source-as-of dates, and sensitivity policy through runtime envelopes.

Target: v1.4.4a parallel app-surface lane Current revision: V1.2 L0 approved Waves: 7 (W0 gate + W1-W6) Parallel agents: 3 peak Source: Linear v1.4.4 project

Source and scope

This is the consumer half of the substrate repair.

A parallel producer-remediation plan is making get_entity_intelligence richer. This plan makes the app consume that envelope for claim-backed briefing content, without replacing operational shell data or inventing a cache database.

  • Problem: app surfaces and PTY prompt builders still mix raw detail commands, cached prep blobs, legacy db.get_entity_intelligence, and page-local composition as sources for claim-backed intelligence.
  • First surfaces: Daily Briefing at src/components/dashboard/DailyBriefing.tsx and Meeting Briefing through prepare_meeting, refresh_meeting_briefing_full, and src/pages/MeetingDetailPage.tsx.
  • Next surfaces: Account, Project, and Person detail pages. After that, Actions and Email.
  • Lane authority: v1.4.4a is a W0-approved exception/amendment to the v1.4.4 WordPress Surface Migration Tauri-freeze rule. It may touch existing Tauri React surfaces only to change claim-backed data sourcing, trust/provenance rendering, and prompt-input plumbing; no new routes, visual patterns, or UI features. W0 records the exception in Linear and mirrors it into the main v1.4.4 wave packet before W1 starts.
  • Upstream dependency: producer remediation for get_entity_intelligence fills the envelope with neighborhood, touchpoints, relationships, health, threads, metadata proposals, and section caveats.
  • Non-goal: no WordPress migration, no remote processing, no new read-cache database, no wholesale rewrite of dashboard shell data, and no prompt-template redesign beyond the minimum needed for substrate-fed inputs.
  • Threat topology: local-to-local single-user. No new loopback endpoint, remote endpoint, MCP exposure, or SurfaceClient pairing scope ships in this lane. Prompt channels, sensitivity gates, source hygiene, provenance rendering, and log redaction still apply.
  • Authority surfaces: Linear remains canonical for issue approval and reviewer verdicts. Durable review artifacts live under .docs/plans/v1.4.4a-tauri-briefing-entity-intelligence/reviews/.
  • WordPress boundary: v1.4.4a may consume v1.4.4 W1 substrate, but it does not satisfy, replace, or change any W2-W6 WordPress migration acceptance criteria. Any cross-surface contract change reopens or amends the v1.4.4 master/sub-L0 packet before code starts.
  • Composition boundary: this lane is a temporary envelope-rendered Tauri consumer exception, not a new composition-producing wave. If implementation creates substrate-authored composed page output, it must use ADR-0130 Composition; otherwise W6 records whether a later ReactBlockRenderer-over-Composition cutover is required.
  • K-in: docs/solutions/security-issues/prompt-channel-sensitivity-class-sweep-2026-05-18.md, ADR-0093, ADR-0102, ADR-0106, ADR-0108, ADR-0111, ADR-0125, ADR-0130.

Operating principles

Consume the substrate; keep the shell pragmatic.

Claim-backed means ability-backed

Facts, risks, open loops, touchpoints, relationship context, trust summaries, and provenance must come from get_entity_intelligence or abilities that compose it. Legacy detail commands may still provide names, navigation, timestamps, meetings, and explicit mutation affordances.

Prompt input is a trust boundary

Meeting briefing PTY inputs must use a prompt-safe Rust projection of entity intelligence. The projection applies the centralized services::claims prompt-channel sensitivity gate, a subject allowlist, structural sanitization or equivalent JSON-boundary defense, length/invisible-character handling, prompt-version bumping, and canonical fingerprint fixtures. Derived prior intelligence is treated as untrusted input under ADR-0093.

Prompt authority is Rust-only

Only the prompt-safe projection built from EntityIntelligenceEnvelope may enter canonical prompt JSON. Tauri React components, get_dashboard_data, cached prep_* blobs, and page-local composers are never prompt authorities.

No silent bypasses

If a briefing section renders claim-backed intelligence, tests and lint must fail when it sources that section from raw SQL, db.get_entity_intelligence, page-local composers, or legacy AI JSON. Cached meeting output may still render as a read model; it cannot become the source of truth for newly generated claim-backed prompt input.

Cache means stale display, not authority

Current ability envelopes are authoritative for new prompt input and new claim-backed rendering. prep_context_json and prep_frozen_json may keep a previous briefing visible during rebuild only when rendered as stale and bound to the envelope or claim ids that produced it. An unresolved cached claim id is a stale-render failure; a claim-substantive string with no current-or-stale claim binding is a bypass.

Render actor-filtered provenance

Tauri UI uses AbilityResponseJson.rendered_provenance for user-visible provenance and trust treatment. DTO-local data.provenance and per-fact provenance refs can drive counts, bindings, and detail fetches, but cannot be rendered as raw provenance unless passed through the actor/surface renderer.

Actor and surface stay narrow

The Tauri app path uses invoke_ability as Actor::User. This lane does not broaden Agent, McpClient, or SurfaceClient exposure for briefing abilities. Any exposure change needs a fresh /cso pass.

Producers can degrade, not disappear

When a producer slice is unavailable, the envelope must return typed empty, stale, or caveated state with trust and provenance context. A missing producer cannot silently fall back to legacy projections for a claim-backed section.

Wave details

W0 - Boundary and inventory

Inventory every Daily Briefing, Meeting Briefing, entity-detail, action, and email path that currently reads claim-backed intelligence. Classify each read as shell data, rendered claim-backed intelligence, prompt input, cached output, mutation, or operational telemetry.

Pass: Linear issues exist for W1-W6; the main v1.4.4 packet records this Tauri-freeze exception; the no-bypass allowlist distinguishes shell/cache reads, stale bound snapshots, and claim-backed authority; prompt-channel matrix enumerates every channel touched by W1-W5 and cites the gate function plus fixture/lint for each; actor/exposure matrix freezes allowed_actors, required_scopes, mcp_exposure, and client_side_executable descriptor values; Daily Briefing shell-vs-claim split is frozen; W2/W3 minimum producer fields and degraded-state behavior are named; composition exception is recorded; root-route and Meeting Detail baselines plus Suite P cardinality caps are captured.

Pacing

W2 and W3 can run in parallel after W1 only if the prompt-safe projection contract, no-bypass allowlist, Daily split, and minimum producer gates are frozen. W4 does not start until Daily and Meeting proof both pass L2.

Bounding

The first PRs should not chase every PTY caller. They prove two surfaces and add the shared seam. Reports, entity detail, actions, and email follow in named waves.

Migration slots

None expected. If W1 discovers a needed schema or cache table, pause for a W0 amendment and claim slots from the active v1.4.4 migration block before coding.

Open questions

Resolve at W0, not during implementation.

  • Linear topology: W0 should decide whether this lands as new v1.4.4a issues/milestones, as an amendment to existing W1/W3/W6 issues, or as a named parallel lane under the current v1.4.4 project. It is part of the v1.4.4 build window either way.
  • Producer dependency gate: W0 must declare minimum producer fields for W2/W3 and the visible degraded state for each absent field.
  • Prompt quality drift: W3 must decide whether meeting-briefing output parity means exact section parity or improved output with documented prompt-version drift and replay-fixture classification.
  • Daily Briefing data split: W0 must pin which dashboard fields remain shell data from get_dashboard_data and which become ability-backed claim intelligence.
  • No-bypass scope: W0 must freeze the exact file/path allowlist for legacy reads so legitimate shell/cache reads do not get blocked by overbroad grep tests.
  • Workspace-memory adjacency: v1.4.5 file-ingestion substrate is adjacent producer work, not owned by this lane. If W2/W3 chooses file-derived claims as required inputs, W0 names that as a producer dependency instead of editing the v1.4.5 plan.
