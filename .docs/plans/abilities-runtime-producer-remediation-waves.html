DailyOS · Abilities Runtime · Wave Plan

Make entity intelligence genuinely substrate-fed.

Close the producer gaps that make MCP and WordPress see less than DailyOS already knows.

This plan turns the producer audit into a full remediation program, not a one-off account-status patch. The goal is to preserve `get_entity_intelligence` as the generic runtime envelope while adding the missing entity-neighborhood readers, producers, MCP projections, trust caveats, and eval gates that let headless surfaces answer real executive-briefing prompts from the claim-backed substrate.

Target: next v1.4.7 remediation train Waves: 5 Parallel agents: 3 peak Source: audit + Linear follow-ups

Source and scope

The first slice is not the finish line.

The remediation scope is the full producer audit, sequenced so the comparison prompt becomes testable early without losing the rest of the runtime work.

  • Origin audit: .docs/plans/abilities-runtime-producer-audit-2026-05-23.md
  • K-in: ADR-0102, ADR-0128, ADR-0057, ADR-0081, ADR-0088, ADR-0097, ADR-0098, plus the claim-producer trust audit solution note.
  • Non-goal: do not teach MCP or WordPress to bypass the runtime by reading account-shaped schema fields directly.
  • Architecture constraint: every durable assertion enters the claim substrate with provenance, temporal scope, sensitivity, lifecycle, and trust recomputation.

Wave shape

5 waves, hard ordering across, parallel within.

W0 freezes the contract and fixtures. W1 builds the generic neighborhood. W2 makes MCP useful for the comparison prompt. W3 and W4 finish the promised runtime sections and trust semantics. L3 + L5 gate each wave before the next starts.

Wave details

Acceptance criteria by wave.

W0 — Contract hardening

Split Linear follow-ups from the audit, assign migration slots if needed, freeze fixture names, and define the producer contract for neighborhood edges, participation rows, section caveats, and MCP projections.

Pass: L0 approves the wave plan; no open product blockers; fixtures avoid customer-specific data; every producer has a services-owned read/write boundary.

W1 — Entity neighborhood

Add a generic read model for hierarchy, explicit entity links, meetings, attendees, people, actions, email threads, and content relationships. Add participation summary composition without account-only joins.

Pass: account, project, person, and meeting fixtures return relationship edges with source, recency, confidence, inclusion reason, and sensitivity-safe subject refs.

W2 — MCP executive briefing

Widen `dailyos.read.account_status` to return touchpoints, record entries, participation/stakeholder candidates, caveats, and provenance refs. Add subject resolution for natural account names or slugs.

Pass: the executive-briefing prompt can be run in Claude Desktop and receives enough structured DailyOS output to compare against a broad-corpus answer.

W3 — Remaining producers

Fill `threads`, `metadata_proposals`, and work/open-loop producer gaps from linked communication, structured source refs, corrections, conflicts, actions, and captured work evidence.

Pass: envelope sections are no longer empty by default when relevant evidence exists, and deterministic evidence remains a read-model section unless it is a durable assertion.

W4 — Trust, health, cleanup

Generalize health story beyond meeting prep, add section-aware trust/caveats, validate trust recomputation across claim types, and run source-label cleanup through a service-owned backfill.

Pass: trust bands and caveats reflect facts plus derived sections; no legacy placeholder source labels remain in user-visible source summaries after backfill.

Release gate

Integrated acceptance criteria.

The full remediation is done only when the runtime can answer the executive-briefing shape without account-only bypasses.

  • `get_entity_intelligence` returns claim-backed facts, open loops, touchpoints, participation evidence, threads, metadata proposals, health story, record entries, section caveats, trust, and provenance when supporting evidence exists.
  • MCP and WordPress consume abilities/runtime output, not parallel schema adapters.
  • The same producer/read-model shape works for account, project, person, and meeting fixtures.
  • The host-model comparison prompt can produce a useful executive briefing with commercial status, risks, wins, stakeholder candidates, influence analysis, and priorities.
  • Trust recomputation and section caveats prevent unsupported assertions from rendering as equally certain as source-backed facts.
  • All gates pass: cargo clippy -- -D warnings, cargo test, pnpm tsc --noEmit, L2 unanimous, L3 S/P/E, and L5 drift check.

Pacing

No wave starts until the prior wave clears L3 + L5. No agent codes before L0 clears unanimously. Two revision cycles trigger L6 escalation.

Bounding

L2 is bounded by acceptance criteria and ADR contracts. Path-alpha findings go to maintenance unless they violate this remediation's explicit contract.

Migration slots

Reserve slots in W0 only if new persisted schema is required. Prefer read-model producers before adding tables.
