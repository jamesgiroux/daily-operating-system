## §1 — Why WC exists

Verified root causes (audit + cycle-1 reviewer verification; file:line in the audit doc and reviewer reports):

1. **Stage 5 is split — and the canonical front door is locked.** The ADR-0123 path has zero UI writers; cycle-1 feasibility review established *why*: `submit_claim_feedback_command` requires envelope binding (`commands/claim_feedback.rs:91-99`), and the envelope-registration wiring (`record_envelope_for_render`, `entity_intelligence/envelope_cache.rs:170`) has **zero production callers** — the command rejects 100% of callers by construction. Meanwhile UI thumbs/corrections write legacy `entity_feedback_events` (`services/feedback.rs:309`), which feeds the **generation side** (`signal_weights` → prompt context, self-healing) but never the **scoring side** (Trust Compiler); the typed path feeds scoring but not generation (ADR-0138 Context). The same human judgment does half a job depending on which door it enters.
2. **Stages 2+3 are fused in enrichment.** Enrichment extracts claims (healthy — via `commit_claim()`) AND writes stage-3 output (`entity_intelligence` snapshots, `services/intelligence.rs:2070-2086`) in one pass. Cycle 1 established the live reader set is **much wider** than first stated — report generators, workspace markdown exporters, MCP handlers, hygiene matchers, prep itself (Decision A) — so WC's retirement yield may be near zero fields; the inventory and per-field retention contract are the deliverable.
3. **Stage-3 inputs duplicate.** Five identical fetches implemented twice (`intelligence/prompts.rs:308-409` vs `prepare/meeting_context.rs:358-423`; same DB handle, sync — extraction is mechanical). **Cycle-1 correction:** the audit's "prep is blind to email signals and stakeholders" was **partially stale** — prep injects both later in the file (`meeting_context.rs:857-879` email signals, `:947-956` stakeholder insights). The remaining gap is richness (e.g., thread grouping at `prompts.rs:680-700`), not absence; C3's first L1 step re-verifies.
4. **Loop arrows leak (C4).** Orphaned emissions with zero consumers (`ClaimTrustChanged`, `trust_recompute.rs:1253-1268`; `meeting_prep_status_changed`, `meeting_prep_status/write.rs:241`); `google.rs:851` writes `prep_invalidation_queue` directly past the bus; claim-feedback validation differs per surface by design history, not intent.

Verified healthy — guard, don't touch: `commit_claim()` gate + one-transaction corroborate/contradict/supersede (`claims.rs:6788-7080`), commit locks (`claims.rs:6481`), PRE-GATE tombstones (`claims.rs:6602-6628`); the 31-mechanism background-execution inventory; delta+consolidated reliability pairs; `prep_context_json`/`prep_frozen_json` (**ADR-0086** — cycle-1 fix: previously mis-cited as ADR-0101); `claim_receipt:invalidated` event bridge.

## §3 — Binding decisions

### Decision A — Enrichment split is reader-gated; expected WC retirement yield ≈ 0 fields; the inventory IS the deliverable (C0 · DOS-860)

Enrichment keeps extracting claims through `commit_claim()` (untouched). Stage-3 snapshot emissions retire **field-by-field, gated on reader migration**. Cycle-1 reviewers established the known reader classes, which the L1 inventory must cover at minimum:

reports (`reports/account_health.rs:78,238-242`, `reports/swot.rs:79-83`, `reports/ebr_qbr.rs:94-98`), `risk_briefing.rs`, workspace markdown/export artifacts (`accounts.rs:332-393`, `people.rs:243,456`, `projects.rs:205`), recommendations UI (`RecommendedActions.tsx:72`), hygiene (`hygiene/{matcher,detectors}.rs`), MCP (`mcp/main.rs`, `bridges/mcp.rs`, `mcp_v2/handlers/tool_account_status.rs`), `workflow/deliver.rs`, `commands/accounts_content_chat.rs`, `services/{derived_state,sensitivity,claim_files}.rs`, and prep (`prepare/meeting_context.rs:896`).

Because reports and workspace exports are long-lived (reports-track is way future), **most fields will carry live readers with no near kill date — WC may legitimately retire few or zero fields.** That is success, not failure: C0's WC deliverables are (a) the verified per-field reader × retention table (every known live reader gets an explicit per-field retention decision and kill-date owner: DOS-858, W4, or reports-track), (b) write-stop for any zero-reader fields found, (c) manual enrich commands → stage-2 "refresh claims" semantics, (d) a clobber-guard test for `merge_user_confirmed_values` read-modify-write (`services/intelligence.rs:2057-2061`) so partial retirement can't clobber retained merged fields. The schema is column-per-field (`migrations.rs:6781-6801`), so grep-based field-level attribution is tractable. **Coupling note (cycle-1):** the legacy snapshot upsert *deletes* feedback rows (`services/derived_state.rs:1074-1085`) — that site is owned by **C2** (lane B) and must land before C0 touches the snapshot writer (Decision E).

### Decision B — C2 executes ADR-0138 Phases 1–2; envelope gate retired for first-party Tauri (DOS-856)

**B.0 — Entry path (decided with James, cycle 2):** envelope binding is **retired as the first-party Tauri contract**. The envelope-registration wiring was never landed (zero production callers of `record_envelope_for_render`); the command rejects all callers by construction. First-party Tauri feedback flows through claim-target resolution → `record_claim_feedback` directly — the pattern `services/recommendations/feedback.rs:70-80` already proves in production. MCP keeps target-handle + watermark (ADR-0137). The envelope cache and `submit_claim_feedback_command`'s envelope gate are removed or parked with the decision recorded in the ADR amendment; if DailyOS ever becomes multi-user/remote, render-binding is rebuilt then. Superseded commands deregistered/feature-gated; registry guard updated same PR.

**B.1 — One writer, effect-tuple fan-out (ADR-0138 §1–2).** Hooks (`useIntelligenceFeedback`/`useIntelligenceCorrection`) route through the legacy→typed mapping table *as specified in ADR-0138* (`confirmed`→`ConfirmCurrent`; `corrected`→`NeedsNuance` + user-authored superseding claim; `dismissed`→`MarkFalse` **or** `NotRelevantHere`/`SurfaceInappropriate` — the intent split is forced in UI copy; `annotated`→user-authored context claim; `rejected` retired). The legacy side effects are **absorbed into effect tuples, not dropped**: `signal_weights` alpha/beta updates, self-healing hook, health recalc via claim→snapshot propagation (ADR-0138 §4 — also the durable fix for WR's R4 snapshot-propagation problem). This is what keeps the generation-side learning loop alive (cycle-1 codex blocker 2 / feasibility advisory 6).

**B.2 — Targeting (ADR-0138 §3).** Composition surfaces pass `claim_refs` (mechanical). Legacy field-targeted surfaces go through the **field→claim resolution adapter** (extending `resolve_intelligence_source`; claim-shaped projections resolvable via subject+type+field_path, `claims.rs:3030`). **Unresolvable channels do NOT get a fabricated fallback** (cycle-1 feasibility blocker 2: `claim_feedback.claim_id` is NOT NULL, and WC is a no-migration wave): a channel whose field has no backing claim **stays on the legacy writer**, dual-written, with a named Phase-3 migration owner — per ADR-0138's no-flag-day sequencing. The C2 AC is inventory-based accordingly.

**B.3 — ADR amendment (one document, decided with James):** ADR-0123 consumption becomes **event-sourced** — trust full-recomputes per subject (`trust_recompute.rs:1108` is correct); `applied_at` marking dropped from the contract, including the residue: `applied_at_pending` writer response (`claims.rs:8015-8020`), MCP field exposure (`tool_claim_feedback.rs:197,265`), stickiness `COALESCE(applied_at, submitted_at)` (`correction_stickiness_eval.rs:368-369,397`). The same amendment finalizes ADR-0138 (Proposed → Accepted) with B.0's envelope decision recorded.

**B.4 — Ledger + first deliverable.** `entity_feedback_events` dual-written during migration, then **frozen read-only** (ADR-0138 §5 — not "projection"). The C2 deletion site at `derived_state.rs:1074-1085` (legacy snapshot upsert erasing feedback rows) is fixed in this stream so dual-written history can't be wiped by enrichment. **First L1 deliverable: the enumerated channel table** — every feedback-entry channel (file:line), classified `wired | dual-written | legacy-pending(owner) | retired` — which becomes the checklist L2 verifies (cycle-1 scope-guardian blocker 1). Kill `intelligence_feedback` writes (`db/intelligence_feedback.rs:112`); UNION-ALL shim stays (drop in DOS-864).

### Decision C — One fetch per concept; premise re-verified; windows documented (C3 · DOS-861)

### Decision D — Signals: consumer, audit-only, or gone; shared eligibility core, per-surface binding (C4 · DOS-862)

Per orphaned signal: register a real consumer, reclassify audit-only, or delete the emission — disposition at L1 with evidence, inside the ADR-0115 policy-registry model. `google.rs:851` stops writing `prep_invalidation_queue` directly; the replacement **signal payload carries the exact meeting ids** from `outcome.prep_invalidation_meetings` so invalidation parity is per-meeting, not best-effort entity matching (cycle-1 codex blocker 5), emitted through `emit_or_log` wrappers. Claim-feedback validation: extract the **shared post-resolution eligibility core** (claim active / surfacing-active / renderable-for-actor) called by both surfaces; binding stays per-surface (Tauri = direct-writer resolution per B.0; MCP = target-handle + watermark per ADR-0137) — cycle-1 established the binding stages are different beasts and "rejected on one ⇒ rejected on the other" only holds for the eligibility core. Derived-state subscriber registry: populate or remove. No-bypass grep lint ships same PR, labeled best-effort.
