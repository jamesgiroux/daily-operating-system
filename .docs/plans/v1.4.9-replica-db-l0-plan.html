DailyOS · v1.4.9 W1 · Substrate Reset

The dev workflow must be structurally incapable of touching the production database.

An L0 plan for DB-mode isolation — Live / Replica / Mock — so a rebuild-and-pkill loop can never again corrupt the real personal-intelligence DB.

The 2026-05-28 corruption was not a substrate flaw. It was a dev-workflow artifact — tasks/lessons.md:5: “Do not edit Rust backend files while pnpm tauri dev is writing to the production SQLCipher DB; hot-restarts terminate WAL writers → btree corruption.” All three root causes are patched (PR #416). The durable fix is structural isolation: production runs untouched; the dev loop runs against a production replica (real content — Glean connectors only work on real account names) or a mock fixture set. This unblocks the safe nuke + fresh-install and lets DailyOS run in production daily without corruption or migration fear.

Why this exists

The hazard is the developer loop, not the user.

A real user never pkills a hot WAL writer. The developer does — on every kill-to-apply-a-fix rebuild — and today that loop runs against the same ~/.dailyos/dailyos.db that holds the real personal-intelligence graph. Isolate the loop from production and the corruption class cannot recur.

What the panel caught

Three convergent blockers killed the “small flag” framing.

BlockerWhy the naïve flag failsDesign response
B1 · Not process-wide enough dailyos-mcp + maintenance bins are separate processes with their own main(); none set the mode → default → prod. MCP launched by Claude/Cursor with no env opens prod and writes audit/recovery state. DB mode is an immutable library bootstrap contract used by every binary (app, MCP, doctor, maintenance, tests). Set once, Acquire/Release, before any thread or open.
B2 · Default-Live isn't a boundary beforeDevCommand starts Vite, not the backend; IDE runs, cargo tauri dev, cargo run, doctor all skip it. Default-Live means any no-env launch hits prod. Fail-closed: non-release builds default non-Live; Live requires explicit --live / DAILYOS_DB_MODE=live. A no-env dev process can never fall through to prod.
B3 · db_path() guard too narrow Misses explicit-path opens (open_at), backup/restore/refresh, and — worst — devtools forces Live on invariant mismatch (exact wrong failure mode). Key cache is path-blind, so the path layer is the only barrier. Structural prod-open deny at open_resolved_path() — the one chokepoint every open passes, before key fetch or file touch. Assert: mode != Live && path == prod → hard error.

The hardened design

Three modes, each a full policy — not three labels on one path.

Reviewers flagged that a mode mixes data source, workspace, config, migrations, external services, and clone direction. Each axis is specified, and ~8 mode-blind ~/.dailyos sites (incl. the hardcoded Google OAuth token) must route through the mode-aware resolver.

Scope — revised

This is isolation substrate, not flag plumbing. Split it.

820-A · safety core

Mode bootstrap contract (every binary) + fail-closed default + structural deny at open_resolved_path(). Lands first; alone makes prod safe and unblocks the fresh-install.

820-B · resolver

Per-mode workspace/config resolver + the ~8 subdir sites (Google token, audit, enrichment, integrations) + devtools fail-closed fix.

820-C · clone

replica-refresh (DB + workspace, read-only source, checkpointed) + destructive-command guards.

Open — James's calls

Three decisions before implementation.

D2 · dev default mode

Which non-Live mode does pnpm tauri dev land in?

Rec: Replica (real content; Glean works; closest to reality), with --mock opt-in for surface-state testing.

D3 · workspace isolation

How is the replica workspace isolated?

Rec: full copy to ~/.dailyos/replica-workspace/ (dotfolder — isolates dev writes AND fixes the iCloud/Spotlight exposure). Cost: disk + clone time.

D5 · governance

SQLCipher-drop sequencing?

Rec: decouple — dropping at-rest encryption is a standing ADR-0092 decision and needs its own ADR amendment, not part of this ticket.

Done means

The regression that defines done: prod DB byte-identical across a dev pkill.

Mode set at bootstrap in every binary, no silent default, non-release fail-closed to non-Live. Structural deny proven from a spawned thread AND a separate process. All workspace/config/Google-token/audit sites resolve per mode (CI-gated). start_fresh_database + restore refuse prod from non-Live. pnpm tauri dev + a pkill leaves dailyos.db mtime unchanged. replica-refresh produces a consistent replica from a read-only prod source. DoD gates: cargo clippy -- -D warnings && cargo test && pnpm tsc --noEmit.
