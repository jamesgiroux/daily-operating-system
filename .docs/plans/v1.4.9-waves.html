Cross-wave decisions (cycle-4 resolved)

The eight architecture calls.

1 · Drop SQLCipher (amend 0092)

L6-approved. DOS-831 amends ADR-0092 directly because ADR-0136 is already occupied. Retire SQLCipher, DB-key recovery, PRAGMA key, encrypted backups, and rekey paths; FileVault / OS disk controls become the DB at-rest boundary. Non-cipher hardening remains active unless separately amended.

2 · Fail-loud + rebuild

No automatic cipher-to-plain conversion path. Existing encrypted-looking, empty, or truncated DBs fail loud with storage-health/rebuild/restore guidance; DOS-832 owns rebuild after correction-preserving projection. DOS-831 is gated from environments with encrypted active DBs unless rebuild is validated or a storage-reset cutover is machine-verified by the release gate.

3 · Corrections survive rebuild

Content-identity correction-journal sidecar (compute_dedup_key shape, not raw runtime dedup_key); replay respects claim_state (no tombstone resurrection); tie-break + orphan-when-ambiguous; exact derivation → DOS-832 L0. Amends ADR-0048 P-4.

4 · Files-as-projection

Edit = correction input via services/claims.rs typed FeedbackAction (ADR-0123/0126); Actor::User; workspace-confined; sensitivity re-validated. Never files-as-truth.

5 · Single-writer ownership

647/758 consume ADR-0133/0134 + the db-lock-storm-class doc verbatim. The only hard prerequisite for the loop.

6 · Centralized trust rendering

One provenance + trust-band + sensitivity renderer for app and MCP (ADR-0105/0108). W5 is parity, not a second renderer.

7 · MCP writes via ADR-0128 §D

169/170 reconcile against §D (already authorizes submit.action/submit.action_status) — confirm it survived reconciliation; not a new amendment.

8 · Migration slots

Dev head v276; next free v277. W1b v277 only if DOS-831 truly needs a marker; DOS-832 adds no migration. W2 v278–279 · W3 v280–283 · W4 v284–289 · W6 v290–295.

Wave detail

What each wave carries and proves.

W1 — DB ownership + storage hardening · substrate

W1a (gating): DOS-647 single-writer + priority lane; DOS-758 request-scoped DB/services + nested-writer guard; DOS-823 (820-C) replica-refresh (consumes shipped 820-A DbMode + run_chunked_backup) + destructive-command guards, completes DOS-820.

W1b (parallel): DOS-831 cipher-drop (ADR-0092 amendment + 820-A DB-mode ADR; fail loud on encrypted input and route rebuild to DOS-832); DOS-832 rebuild-from-canonical, corrections-preserving (depends on W3); DOS-767/768/770/812 ingestion-hygiene.

Proof — substrate; replica-refresh clones prod→replica read-only, prod-destroyers refuse outside the guard, a rebuild reproduces the working DB including user corrections.

W2 — Security right-size · substrate (parallel)

DOS-833 strips HMAC/pairing/nonce/scope-grant for local same-OS-user; supersedes/amends ADR-0102 + 0128 (they still mandate the auth) and names replacement gateway/auth paths; preserves Actor::McpClient vs User for provenance. DOS-510 hostile-input proof re-scoped to §1 (consumes ADR-0093).

Proof — local invoke + MCP loopback parity, no signing ceremony; hostile-input fixtures pass.

W3 — Claims → editable readable files · first loop slice

DOS-628 projects claims→markdown out (ADR-0105 envelopes) + the structured corrections sidecar; file→claim write-back as Actor::User, workspace-confined, sensitivity re-validated, typed FeedbackAction. File-read content is ADR-0093 Tier-2-classified/Tier-3-handled (wrap_user_data); ADR-0108 log hygiene. New producer ⇒ full trust-recompute audit on the write-back path.

Proof — edit a claim's file → claim updates as a new correction source, provenance records it, projection re-renders, derived state reacts.

W4 — Judgment moat / correction loop · HEADLINE

DOS-834 propagation/invalidation (keystone) · DOS-8 feedback · DOS-318 contradiction (fork not winner, ADR-0126 §6) · DOS-443 review-queue budget (§8) · DOS-447 render suppression (ADR-0125 registry) · DOS-316+811 deviation (§5) + expected_presence · DOS-338 eval harness (extends bridges/eval.rs; cross-surface, post-re-enrichment, indirect-surfacing stickiness) · DOS-446 fixture · DOS-278 count bug · DOS-277 agenda survival (felt-stickiness keystone) · DOS-317 engagement→ranking (ADR-0126 §9, ranking not trust).

Irreducible core if the wave compresses: DOS-8 + DOS-834 + DOS-277 + DOS-338.

W5 — MCP-first parity · loop over MCP

Definition of done

Version-tag gates.

  • Headline proven + felt: a correction in app, file, and MCP each changes a surfacing the user did not directly touch, survives re-enrichment + rebuild, measured by DOS-338.
  • Substrate reset: plain SQLite (ADR-0092 amendment landed); encrypted-looking, empty, or truncated stores fail loud into restore/rebuild guidance; DOS-831 release/cutover gate prevents stranding encrypted active DBs before DOS-832 is available or a storage-reset cutover is machine-verified; rebuild preserves corrections; single-writer; replica-refresh + guards (DOS-820 closed); auth right-sized + threat-model/0102 supersession.
  • Cross-surface parity modulo the ADR-0125 sensitivity gate (Confidential/UserOnly app-only).
  • No stubs in shipped waves: contradiction.rs / render_rules.rs / deviation.rs / recommendations/eval.rs real.
  • Gates green: cargo clippy -- -D warnings && cargo test && pnpm tsc --noEmit (DOS-824 flake tracked separately).
  • W6 is not a tag-gate (release valve).
