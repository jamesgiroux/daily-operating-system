Build waves · post-Gate-2 · coarse by design

W1A–W5 — build the primitives, delete the taxonomy.

Not conversions: each wave ships a primitive end-to-end, then deletes every legacy surface that primitive answers — and per the codex L0 fold, no operational page dies before the Queue owns its operations (Library is retrieval; Queue is operations). Ordering per the panel: grammar on existing producers first, the Day from the existing bounded producer second, the new prompt/streaming machinery third. Old routes stay addressable until the new surface survives daily use; an old/new output-equivalence check rides each deletion.

Operating rules

The whole control surface, restated once.

Two gates, no covenants

Gate 1 (latency checkpoint) and Gate 2 (instrumentation readout) are the only program-level gates. Everything else is the normal ladder: per-ticket L0, L2 before merge, L4 on user-facing waves.

Deletion is the acceptance criterion

A wave is done when the surfaces it answers are deleted. The measured precedent (two generations left in-tree, 27 orphans) is the named failure mode. Old routes stay addressable until the new surface survives daily use.

Substrate changes run their own L0s

Any wave item touching claim semantics, the writer queue, the abilities contract, or the composition model beyond consuming them exits the wave and runs as substrate work (ADR-0139 sequencing rule). Documents-as-saved-queries consumes producers; it does not re-architect them.
