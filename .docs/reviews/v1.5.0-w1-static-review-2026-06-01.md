## Findings And Resolutions

| Priority | Finding | Resolution |
|---|---|---|
| High | `ProjectedSection.block_indexes` stored original composition positions while the Account page used them as indexes into the compact projected `blocks` array. Dropped unknown blocks could make later sections render empty/misassigned blocks. | Section block indexes now use post-drop projected array positions; `ProjectedBlock.block_index` remains the original composition/audit position. `projected_sections_preserve_safe_outline_and_skip_dropped_blocks` asserts both contracts. |
| High | `useProjectedComposition` could keep prior account data visible during navigation and allow late responses to overwrite the active account. | The hook now clears data when account identity changes, preserves data for same-account refetch, and guards async updates with a monotonic request id. Tests cover stale response suppression and account-change clearing. |
| Medium | Mixed claim+snapshot sections dropped snapshot-backed fields whenever a section had any claim blocks. | `build_claim_or_snapshot_section_blocks` now appends a snapshot evidence block after claim blocks when both inputs exist. A new account-overview test asserts claim evidence and snapshot evidence render together. |
| Medium | Fallback/custom renderer DOM attributes exposed raw block ids and original custom type ids even though the text renderer hid them. | Runtime block components no longer write `data-block-id` or `data-original-block-type`; tests assert the fallback article omits those attributes. |
| Low | The render-orchestrator module docs claimed cache-hit/audit behavior the shared helper does not perform. | Updated the module docs to describe the actual cache/project/return behavior without claiming audit emission/drain. |
