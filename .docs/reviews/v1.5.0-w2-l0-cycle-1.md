## Remediation Applied

- Overlay identity is now `(entity_type, surface_key)` only.
- `overlay_schema_version` is defined as persisted JSON format metadata.
- `layout_revision` is defined as service-owned presentation/cache state, separate from producer composition version and not part of identity.
- Migration 275 now requires idempotent DDL and replica migration smoke before W2 proof.
- Core locked content now aligns to masthead and lead; W1 `headline` keys must map to lead semantics if used.
- `useChapterLayout` now requires latest-wins optimistic mutation sequencing and tests for stale save/reset responses.
- Edit-mode tests/proof now cover accessible names, keyboard instructions, move/drop/cancel announcements, focus restoration, and locked-control explanations.

## Path-Alpha Notes

- Include an L1 rationale for using a dedicated `composition_layout_overlays` table instead of generic key/value app state.
- Prefer a new `commands::composition_layout` namespace that delegates to services.
- Keep inline label overrides restricted to section/display labels; claim text edits must route through feedback/correction.
- Keep W2 proof focused on unknown-payload leakage, failed-save rollback, keyboard drag-and-drop, and no per-block backend fanout.
