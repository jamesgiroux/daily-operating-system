## Blocking Findings

### 1. Stale initial overlay loads can overwrite local edits

**Severity:** P2, AC blocker

**File:** `src/hooks/useChapterLayout.ts`

When Account Detail has a projection but `getCompositionLayoutOverlay` is still pending, the edit controls are already usable. If the user hides or reorders before the load resolves, the load handler applied the older overlay unconditionally and could overwrite the optimistic edit or save response.

**AC impact:** Violates W2-B latest-wins optimistic mutation behavior and W2-D live update expectations.

### 2. Overlapping failed saves can preserve unsaved optimistic state

**Severity:** P2, AC blocker

**File:** `src/hooks/useChapterLayout.ts`

With two quick layout changes before either save resolves, if both requests fail, the second failure rolled back only to the previous optimistic state captured after the first change. The UI could keep the first change even though no backend save succeeded.

**AC impact:** Violates W2-B latest-wins persistence behavior and can make the visible layout disagree with saved overlay state until reload.

## Remediation Plan

- Track the acknowledged persisted overlay and revision separately from optimistic local overlay state.
- Ignore initial load responses if a local mutation sequence changed after the load began.
- Roll back failed latest saves/resets to the last acknowledged persisted overlay.
- Add regressions for stale initial load versus local edit and overlapping failed saves.
