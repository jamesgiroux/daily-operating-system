## Findings

| Priority | Finding | Resolution |
|---|---|---|
| P2 | Missing or deleted accounts could still compose an empty account page when the claim reader returned no claims and the account snapshot reader returned `AccountNotFound`. | `dailyos/account-overview` now treats `AccountNotFound` as a validation error before commit. Snapshot read failures still degrade, preserving real-account empty/degraded rendering. Added `missing_account_snapshot_rejects_before_composition_commit`. |
| P2 | Projector generic fallback blocks emit `selected_known_type_id: "dailyos/text"` with a safe banner, but the React renderer did not handle that fallback type and showed a generic unavailable state. | `ReactBlockRenderer` now routes `dailyos/text` through `GenericTextBlock`, preserving the fallback banner and safe text/body payload. Added renderer regression coverage. |
| P2 | Frontend provenance status required exact field-attribution path matches and used the global composition source count, so parent/detail coverage and truncated attribution maps could show false `Source pending` labels. | Block provenance resolution now accepts parent/detail field-path coverage, counts the matched attribution's `source_refs`, and degrades to recorded provenance when render-budget truncation removed detailed attributions. Added coverage for covered paths and truncated provenance. |
| P3 | `get_projected_composition` counted cache hits as successful ability invocations even when the producer closure did not run. | The command now records `ability_invocation_count` success only when the projection was not served from cache. Added a focused helper regression. |
