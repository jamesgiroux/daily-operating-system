## Stream 1 — Local-first desktop data + shell stacks (fed the case doc §4)

**Question:** building DailyOS's data+shell foundation today, unconstrained, what would we pick?

**Findings:**
- **Desktop shells:** Electron still dominates by install base (Obsidian, Notion, AFFiNE); Tauri 2.x (stable, v2.10.x) is the serious challenger — 2–10MB bundles, ~30–50MB idle RAM; for macOS-only the WebView-fragmentation risk vanishes. Dioxus/Flutter desktop: pre-production / thin ecosystems. **The "Tauri + Rust + React" stack we're on is the frontier-correct choice for macOS-focused apps.** Native SwiftUI only rational if App Store distribution is a business requirement.
- **Local-first reactive data layers:** LiveStore (event-sourced, materialized SQLite projections, reactive queries; beta; **no native Tauri adapter** — web adapter only, verified against its own docs during red-team); TanStack DB 0.6 (differential dataflow, SQLite persistence in Tauri/Electron; client cache layer, no event-sourcing); Zero/ElectricSQL (server-required — mismatch); Jazz/Automerge (CRDT, solving multi-device sync we don't have); Triplit (post-acquisition risk).
- **SQLite evolution:** single-writer WAL unsolved in mainline (BEGIN CONCURRENT in hctree branch only); the correct 2026 answer is *design around it* — single write actor + WAL readers. libsql/Turso embedded reduces lock hold time but adds a fork dependency. **DuckDB v1.5 reads SQLite files directly** (first-party extension) for OLAP-shaped queries. sqlite-vec fine under ~100K vectors (brute force); LanceDB for ANN at scale.
- **Background jobs:** SQLite-as-durable-execution-log (Morling pattern) fits desktop; Restate self-hosted (~30MB sidecar) is the principled durable-workflow answer if ever needed.
- **The architectural verdict that shaped everything:** *the 8.8s page load is a CQRS violation, not a SQLite bug* — OLAP-shaped UI reads against the OLTP store under enrichment write load; the missing piece is a materialized read layer, not a database swap.

Key sources: johnny.sh sync-engine survey 2026, TanStack DB 0.6 release, LiveStore docs/GitHub, sqlite-vec, DuckDB embedded-DB comparisons (Kestra), Morling durable-execution-with-SQLite, Turso concurrent-writes, Tauri-vs-Electron 2026 (Rustify), AFFiNE architecture.

## Stream 2 — AI-native application architecture + experience paradigms (fed the case doc §4)

**Findings:**
- **Generative UI converged on declarative dispatch from typed catalogs:** A2UI (Google, v0.9→1.0; production in Opal/Gemini Enterprise; agent emits validated JSON referencing pre-approved components — never raw markup); AG-UI protocol (CopilotKit, $27M raise; SSE event-sourced agent↔UI streaming; Microsoft/Google/Amazon adoption); MCP Apps (SEP-1865, `ui://` resources in sandboxed iframes; launch partners Asana/Canva/Figma/Slack). Vercel's RSC generative UI effectively paused. **This is ADR-0130's pattern, standardized industry-wide.**
- **Personal-intelligence landscape:** Limitless acquired by Meta + Rewind shut down (Dec 2025); Granola $125M Series C at $1.5B (Mar 2026), pivoted notetaker → enterprise AI context layer with MCP; Screenpipe (OSS local capture, SQLite+FTS5); mem0-class memory stacks at 94.4% LongMemEval. **Unsolved per the field's own state-of reports: staleness, salience, provenance depth, trust bands** — exactly our claims substrate.
- **Agent runtimes:** OpenAI Agents SDK (resumable sessions); Apple WWDC 2026: Foundation Models (3B on-device, multimodal, free) + Core AI (bring-your-own local model) + provider-swapping in macOS 27 — the on-device classify/extract + frontier-synthesis tiering pattern.
- **Experience paradigm — post-chat is the convergence:** "chat is what shipped, not what works" (UX Collective); ambient copilots shipping 4× chat-first with 3× engagement (treat figures as directional — red-team struck them from the case for being unsourced); Google's Daily Brief and Siri AI (WWDC 2026) both bet push-first briefings; ChatGPT Pulse attempted and paused. Four-stage model: markdown → inline generative UI → chat-as-builder → self-composing interface; trust/explainability named the blocker for stages 3–4.

Key sources: A2UI Google dev blog, AG-UI/CopilotKit TechCrunch, MCP Apps announcement + WorkOS analysis, mem0 State of AI Agent Memory 2026, Granola Series C (TechCrunch + granola.ai), Apple WWDC 2026 coverage (Callstack, TNW), UX Collective "chat box isn't a paradigm," designproject.io four stages, AlphaSense proactive-AI principles.

## Stream 3 — Claude Cowork + Anthropic platform leverage (fed the vision's platform-leans table)

**Findings:**
- **Cowork** (Jan 2026 research preview): GUI agentic desktop for non-technical users; folder grants on local files; scheduled tasks; connectors (Drive, Gmail, DocuSign, FactSet). Outputs land in per-session paths (no persistent output folder — open issue #47179); artifacts export PDF/DOCX/MD; live artifacts are non-exportable HTML dashboards.
- **The hard constraint: Cowork consumes only REMOTE MCP servers** (cloud-brokered; confirmed in Anthropic support docs). Our local MCP server works with Claude Desktop and Agent SDK today, but Cowork can't reach it without public tunneling. **Cowork works on our files, not our tools.**
- **Claude Agent SDK** (stable; TS + Python): full agent loop, hooks (PreToolUse/PostToolUse/Stop/SessionStart), resumable sessions, subagents, **local MCP client support**. June 15 2026: subscription Agent SDK usage moves to a separate credit pool — metering matters for ambient use. No Rust variant — embedding means Node sidecar (externalBin precedent exists) or CLI `--output-format stream-json`.
- **Managed Agents** (Apr 2026 beta): hosted sandbox, $0.08/session-hour + tokens; prototype-with-SDK, promote-to-managed pattern.
- **MCP Apps `ui://`:** spec final; Claude-client rendering buggy mid-2026 (issues #287/#671 — EmbeddedResource not surfaced). Revisit late 2026.
- **Boundary pattern (Obsidian/Notion prior art):** host app stays source of truth; agent writes to defined zones in open formats; the claude-obsidian project's wiki/-vs-raw/ write separation mirrors our correction-loop needs.
- **Synthesis table (capability → posture):** trust rendering/ambient/corrections/push = native; long-form doc gen = Cowork via grantable folder; substrate-touching background synthesis = Agent SDK (sidecar/CLI); in-Claude UI = defer.

Key sources: anthropic.com/product/claude-cowork, Claude Help Center remote-MCP article, code.claude.com Agent SDK docs, MCP Apps blog + GitHub issues #287/#47179, CNBC Cowork coverage, claude-obsidian GitHub.

## Stream 4 — OSS building blocks for a prompt-composes-document app (fed the vision's Document/Library mechanics)

**Findings:**
- **Block editors:** Plate v53 (16.3k stars, `streamInsertChunk()` + suggestion-nodes ≈ tracked-changes; Slate perf cliffs + heavy release churn; migrating our 19 renderers = 1–2 sprints); Tiptap + AI Toolkit (paid add-on; schema-aware streaming custom nodes; read/write fences); BlockNote (fast to ship, less extensible); Lexical (perf champion, steepest custom cost); BlockSuite (Lit/web-components — wrong fit); Milkdown (minimal ProseMirror).
- **Streaming markdown:** Streamdown (Vercel, 5.3k stars — the production standard for unterminated-block streaming); llm-ui (custom block-marker syntax triggers React components mid-stream); react-markdown+remark/rehype for completed output; MDX-at-runtime patterns.
- **The markdown question answered:** document-AI products treat **typed/structured output as source of truth and markdown as export/interchange** — validating our Composition-first posture rather than "recalibrate markdown as HTML."
- **The view-vs-artifact idea** (became the saved-query framing, later corrected by L0 to saved-query **+ dated run record**): documents as parameterized queries over the claim graph, Airtable-views-over-one-base analogy; git-working-tree analogy for correction accept/reject.
- **Search:** tantivy proven in Tauri apps (HelixNotes, OmniFile; ~30MB) — *but the K-in review found the in-tree FTS5 + ADR-0074/0078 vector stack must be compared first; the drafted L0 (`.docs/plans/v2.0-search-substrate-l0-draft.md`) recommends extending existing primitives, no tantivy.*
- **Read-mostly rendering pattern:** virtualized block list (tanstack-virtual) + editor activated per-block on edit — avoids importing a full editor stack for reading. **Recommendation: Stack B** — keep our 19 typed renderers, add Streamdown + typed markers + virtualization; adopt an editor only per-editable-block later. Counter-risk recorded: under-investing in editing coordination (undo/selection/keyboard) that Plate ships.

Key sources: BuildPilot editor comparison 2026, Plate GitHub/docs, Tiptap AI Toolkit, llm-ui, Streamdown GitHub, HelixNotes (Tauri+tantivy), tantivy GitHub, Skovy rendering-rich-LLM-responses.

## Stream 5 — Transcripts, generated-doc libraries, prompt-to-briefing product patterns (fed the Day/Library/Prompt primitives)

**Findings:**
- **Transcript-first:** Granola's two-layer document (user notes black / AI gray; raw transcript one click beneath every summary bullet) is the proven trust affordance; organizes by person/org; cross-folder NL queries with citations. tl;dv: multi-meeting intelligence (topic trends across hundreds of transcripts). Circleback: transcript → CRM updates/tasks/follow-ups (knowledge-base substrate). Fellow: prior notes feed next-meeting briefs — calendar as spine.
- **Generated-doc libraries:** Glean's **Library** (named primitive: shared, stable-URL, *refreshable* artifacts), ChatGPT Projects library (explicit, editable memory), Perplexity Pages (thread → persistent cited doc; no in-place refresh). **The junk-drawer is the named failure mode**; no product solves freshness/staleness signaling on old outputs — *"generated from data as of X, here's what changed" is an unclaimed gap.*
- **Prompt-to-briefing state of the art:** Glean's ACME QBR brief (structured one-pager, permission-aware citations, risk list, next actions → Library); Hebbia Matrix (sentence-level citations + Iterative Source Decomposition reasoning traces — the high-trust benchmark, structurally identical to our claim→evidence model); Gemini Deep Research (persistent reports, partial section revision). Composed answer = multi-section document with inline citations, persistent, re-runnable. **Nobody diffs against last week.**
- **Calendar/email:** calendar-as-spine validated across all survivors (Fellow, Read.ai, alfred_, Granola); **email triage inside non-email apps failed at scale** (Clockwise dead Mar 2026, others narrowed) — digest-within-context is the viable form.
- **Entity pages split:** CRM-lineage tools keep standing records + on-demand synthesis overlays; note-first tools aggregate on query. Claim-level entity intelligence with trust bands on personal data: **unclaimed**.
- **Hypothesis scorecard:** transcripts-as-future ✓; generated-doc library ✓; files-invisible-is-a-gap ✓; app-as-prompt-composed-blocks *partially* (market is at "library of docs," not "app IS the prompt" — we'd be ahead); briefing-as-primitive ✓✓.

Key sources: Granola Series C + reviews (Bluedot, Wonder Tools), tl;dv MCP blog, Circleback, Glean artifacts + May 2026 launch + Snowflake integration (Gend), Hebbia April 2026, Perplexity/Gemini/ChatGPT Projects docs, Fellow, alfred_ briefing-tools survey, Salesforce Agentforce Summer 2026.
